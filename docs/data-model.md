# 数据模型

DuckDB 中保留以下规范化实体：

| 表 | 粒度 | 用途 |
| --- | --- | --- |
| `leagues` | 每个联赛 | 赛季与时间范围 |
| `matches` | 每场 BO 比赛 | 阶段、队伍、开赛时间 |
| `battles` | 每个小局 | 日期、局序、时长、胜方 |
| `team_battles` | 每局每队 | 胜负、击杀、经济、防御塔、龙 |
| `player_battles` | 每局每选手 | 位置、英雄、KDA、经济、伤害、MVP |
| `bp_actions` | 每个 BP 动作 | Ban/Pick、阵营、动作顺序、Pick 顺位 |
| `player_items` | 每局每选手每装备槽 | 对局结束时装备快照 |
| `player_runes` | 每局每选手每类铭文 | 铭文 ID、名称和数量 |
| `metadata` | 每个元数据键 | 演示/真实模式与构建时间 |

`battle_id` 是事实表之间的主要关联键。`player_key` 当前由队伍 ID 与选手名组合生成，以避免不同队伍同名选手直接碰撞；若未来拿到稳定的官方 player ID，应迁移为官方 ID，并保留姓名历史维表。

装备只能解释为“接口返回的结束时装备栏”，不能等价于购买顺序。铭文来自局详情的 ID 列表和静态字典；字典缺失时保留原始 ID，避免错误映射。
